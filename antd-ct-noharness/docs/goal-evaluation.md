# 目標の自己評価

## 評価の方法

1. **撮影と目視**：`scripts/capture.mjs`（`brief/scripts/capture.mjs` と同一内容。ESM の import 解決のためプロジェクト内に複製）で 18 状態 × 1440px / 390px（高さ 900px）を撮影し、`screenshots/` を目で確認した。
2. **自動検査**：同じスクリプトで axe（`wcag2a` `wcag2aa` `wcag21aa`）と横はみ出し（`scrollWidth - clientWidth`）を測った。最終結果は **36 件すべて違反 0・はみ出し 0**（`screenshots/report.json`）。
3. **G1・G2 の計測**：`scripts/measure-g1g2.mjs` で、ページを開いた直後に「相手の名前（見出し）」と「ハドルを始める」ボタンの下端がファーストビュー（900px）に入るか、ハドル開始までのクリック数、開始時のスクロール量を測った（結果 `docs/g1g2-measure.json`）。
4. **論証**：目標ごとに「目標 → 意図 → 画面の要素 → 証拠」をたどる。証拠は撮影ファイル名か計測値。

自分で作ったものを自分で評価しているので、下の判定は甘くなりうる（§限界）。

## 目標ごとの論証

### G1 開いてすぐ「今週、自分は誰と話すか」がわかる — 達成（計測で確認）
- **意図**：滞在数十秒で Slack から来る人に、探させない。
- **要素**：組み合わせ画面の最上部の Card「今週のあなたの CT」。相手のアバター（64px）と名前を見出し（h2）で、画面で最も大きい本文要素として出す。日付・曜日・14:00 を同じカードに。
- **証拠**：`screenshots/S01-1440.png` `S01-390.png`。計測で名前の下端は 361px / 422px（ファーストビュー内）。お休みの週（`S03-*.png`）は同じ場所に「今週、あなたはお休みです」、参加者 2 人未満（`S05-*.png`）は「今週の組み合わせはありません」が同じ場所に出る。

### G2 その相手との通話をすぐ始められる — 達成（計測で確認）。ただしチャンネルの決め方は要検証
- **意図**：相手を確かめた直後の視線の先に、唯一の主ボタンを置く。2 人が同じチャンネルに集まれるようにする。
- **要素**：主ボタン「ハドルを始める」と、その下の「#u-misaki で始まります（ペアのうち社員番号が若い人の uチャンネル。相手も同じチャンネルに来ます）」。uチャンネル未設定のペアはボタンを出さず、警告（Alert）で理由と代替（Slack の DM）を示す（`S09-*.png`）。
- **証拠**：計測でクリック 1 回、スクロール 0px。
- **弱いところ**：「社員番号が若い人の uチャンネル」というルールは私の判断で、ブリーフの「相手の uチャンネル」と表現が違う。実際の利用者がこの説明文を読むかは未検証。

### G3 先の週の予定を確かめられる — 概ね達成
- **意図**：自分の予定は開かずに読め、他人のペアは必要なときだけ開く。
- **要素**：カード内の「あなたの今後の予定」（来週／次に話す相手／次のお休み）と、ページ下部「今後の予定」の Collapse。見出しに日付・「予定」タグ（時計アイコン付き）・自分の相手、祝日は赤の「祝日・CT なし」タグと祝日名。
- **証拠**：`S01-*.png` `S04-*.png`（10月12日を開いた状態）。
- **弱いところ**：fixtures の 5 週ではお休みが回ってこないため「次のお休み」は「11月2日までの予定にはありません」としか言えない。範囲外の予定は調べられない。「特定の人と次に当たる日」を調べる機能は入れていない（D30）。

### G4 誰が入っているか確認し、いなくなった人を安全に外せる — 達成
- **要素**：メンバー画面の Statistic（参加 9 / 不参加 2 / 全 11）、List（社員番号順、アイコン付きタグ「参加」「不参加」、警告タグ「初回設定が未完了」）。行ごとの「削除」→ Modal で名前とアバターを示し、取り消せないこと・組み直しを明記。初期フォーカスは「キャンセル」、実行ボタンは危険色。失敗はダイアログ内の Alert で、ボタンが「もう一度削除する」に変わる。
- **証拠**：`S11-*.png` `S13-*.png` `S14-*.png`。axe 0 件で、タグはアイコン＋文字なので色に頼らない。
- **弱いところ**：成功は `message`（数秒で消える通知）と一覧の更新だけで、通知を見逃すと結果は一覧からしかわからない。

### G5 参加状況を変えられ、その影響が伝わる — 達成（文言の妥当性は未検証）
- **要素**：自分の設定画面の Radio「参加する／参加しない（休止する）」。値を変えた時点で警告 Alert「参加をやめると、全員の組み合わせが変わります／保存するまでは何も変わりません」。保存後の Alert も、参加・不参加で文言を変える。
- **証拠**：`S10-*.png`（保存成功）、`S17-*.png`（失敗。入力は残る）。値を変えた直後の警告は撮影対象の状態に無いため、手元の操作でだけ確認した（画像なし）。

### G6 初めての人が迷わず必要な設定を終えられる — 達成
- **要素**：`/setup`。見出し「はじめに、CT の設定をしてください」、必須 3 項目、名前は Slack の表示名が入った状態、参加は「参加する」が初期値。他の画面には「初回設定が済んでいません」の警告と「設定する」ボタン。未入力で送信すると項目ごとのエラー（`S16-*.png`）。
- **弱いところ**：390px では h1 が 2 行になり大きい（`S15-390.png`）。初回にどの画面へ来ても `/setup` に自動で移すのではなく、警告で案内する作りにしている（デモの `state=setup*` で `/` を開いたときだけ自動で移す）。

### G7 どんな状態でも何が起きていて次に何をすればよいかわかる — 達成
| 状態 | 何が起きたか | 次にすること | 証拠 |
| --- | --- | --- | --- |

## 検査の経過（ハーネスなしで、共通の検査だけで見つかったこと）

- 初回の撮影では **36 件すべてで color-contrast 違反**（1 状態あたり 3〜28 ノード）と、S13・S14 で **8px の横はみ出し**があった。どちらも antd の既定のまま組んだ結果で、トークン上書きと同梱 reset.css で解消した（`design-decisions.md` §4）。
- そのほか 390px の S02 で link-in-text-block（文中のリンクが色だけで区別）を検出し、下線で解消。

## 評価の限界

- 作った本人による評価で、利用者による試験はしていない。「迷わず」「すぐ」の判定は計測値（クリック数・位置）と目視による。
- 計測は高さ 900px の固定ビューポート。実際のスマートフォン（ブラウザのツールバー込み）では見える高さが小さく、ハドルボタン（下端 498px）は多くの端末で見える範囲と推測するが、確かめていない。
- axe が見るのは自動判定できる項目だけ。スクリーンリーダーでの読み上げ順、キーボード操作の全経路（Dropdown・Collapse・Modal）は一部しか確かめていない（Modal の初期フォーカスが「キャンセル」になることは撮影 `S13` のフォーカスリングで確認）。
- Modal を開いた状態の全画面撮影では、マスクがビューポートの高さ分にしか描かれていない（`S13-1440.png` の下部）。全画面撮影の仕様による見え方で、実際の画面では起きないと推測する（未確認）。
- ハドルのチャンネル規則・削除権限などはブリーフで未決の事項で、私の判断。チームの運用と合うかは未検証。
- Ant Design の公式ガイドラインに照らした確認はしていない（実験条件）。どこが Ant Design の流儀から外れているかは `post-hoc-lint.md` とハーネスあり版との比較でしかわからない。
