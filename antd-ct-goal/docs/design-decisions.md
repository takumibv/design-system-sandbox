## 主役の決め方

- 利用シーンは「月曜、数十秒の滞在で相手を確かめてハドルを始める」。ハーネスで最も近いのは **SP:research-workbench**（ワークベンチ＝アプリのホーム）の「Reduce Memory Load：戻ってきた人の中心目的への最短経路を出す」「最もよく使う内容を最初の画面に出す」。これをホーム画面の方針にする。
- **DM**「primary はその画面で最も重要な 1 つの操作だけ」「Meaningful：視覚的な強調は操作のために取っておく」、**SP:buttons**「primary はボタン群に最大 1 つ」「Call to Action は 1 画面に 1 つ」→ ホームの primary は「ハドルを始める」1 つだけ（未ログイン時は「Slack でログイン」）。
- ただし「今週の自分の相手を最上部のカードに出す」という**画面構成そのもの**はハーネスに直接の指示はなく、ワークベンチの原則からの**自分の解釈**。

## 決まっていないことの決め方（下書き）

- **どちらの uチャンネルでハドルを始めるか**：ペアのうち社員番号が大きい方の uチャンネルに固定する（2 人が別々の場所で始めてしまうのを防ぐため、ペアで場所を 1 つにする）。画面に「ハドルの場所：u-xxx」と出す。自。
- **削除を誰に許すか**：ログイン中の全員。ただし自分自身は削除できない（自分を消すとログイン中の本人が宙に浮くため）。自。
- **先の週をどこまで**：固定データの全 5 週（今週＋4 週）。自。
- **スマートフォン**：ホームは 390px で G1・G2 を最初の画面で達成する。メンバー・設定も 390px で使える。自。
- **特定の人と次に当たる日**：入れない（主目的から外れる。予定の一覧で代替できる）。自。
- **参加者数**：参加者だけを数え、「参加 9 人・不参加 2 人」と併記する。自。

# 確定版（実装後）

## 1. 主役

**主役は「今週のあなたの相手」カード 1 枚。** 画面の中で primary（濃い青の塗りボタン）はこのカードの「〇〇さんとハドルを始める」だけにした（未ログインなら「Slack でログイン」）。

- 利用は「月曜、数十秒」。そこで要るのは「相手の名前」と「通話の開始」の 2 つだけなので、この 2 つを 1 枚のカードにまとめ、ページの見出し直下に置いた（S01-1440 / S01-390）。
- 根拠：SP:research-workbench「最もよく使う内容を最初の画面に」「戻ってきた人の中心目的への最短経路」、DM「primary は画面で最も重要な 1 つの操作だけ」、SP:buttons「Call to Action は 1 画面に 1 つ」、DM の価値 Meaningful「視覚的強調は操作のために取っておく」。
- **ただし「自分の相手だけを抜き出して最上部に置く」構成自体はハーネスに書かれていない。** ハーネスの記述はワークベンチ（業務アプリのホーム）向けの一般論で、それを「数十秒で終わる確認」に当てはめたのは自分の判断。
- ボタン文言は「〇〇さんとハドルを始める」。SP:buttons「ラベルは動詞で、押すと何が起きるかがわかるように」に従い、相手の名前を入れて押した結果が予測できるようにした。

## 2. 画面構成

ナビゲーションは上部の横並び Menu（SP:navigation「トップナビは項目 2〜7 個、消費者向け・ランディングに向く」）。画面は 3 つ＋404。

| 画面 | パス | 構成 | 主な部品 |
| --- | --- | --- | --- |
| 組み合わせ（ホーム） | `/` | 見出し「組み合わせ」＋開始時刻の一文 → 左列：①今週のあなたの相手（主役） ②今週の組み合わせ（全ペア）／右列：③これからの予定。390px では ①②③ の順に縦積み | Card, Row/Col, Avatar, Tag, Collapse, Button, Alert, Empty, Skeleton, Result |
| メンバー | `/members` | 見出し → 未ログインならログインの案内（Alert）→ 参加・不参加・初回設定未完了の人数（Statistic）→ 一覧（Listy）→ 削除の確認（Modal） | Statistic, Listy, Tag, Modal, Alert, Empty |
| 自分の設定 | `/settings` | 見出し → 失敗時の Alert → フォーム（名前・社員番号・uチャンネル・CT に参加する） | Form, Input, Select, Radio.Group, Alert |
| はじめての設定 | `/setup` | 同じフォームを「はじめての設定」として出す。目的の一文と、各項目に「何に使うか」の補足 | 同上 |

ヘッダー：ロゴ（gaji.jp を別タブ）＋「CTスケジュール」、Menu（組み合わせ／メンバー／自分の設定）、右端にログイン中の人（アバター＋名前。押すと「自分の設定」「ログアウト」）または「Slack でログイン」。390px ではロゴとログイン状態を 1 段目、Menu を 2 段目に分けた（横並び Menu は幅が足りないと「…」に畳まれ、今いる画面が見えなくなるため。自）。

### 画面ごとの判断

- **今週の組み合わせ**：全ペアを社員番号順に並べ、自分のペアは名前を太字にし、Tag「あなたのペア」（アイコン＋文字）を付けた。色だけに頼らない。ペアごとに text ボタン「ハドル」（SP:buttons「text ボタンは表の行の操作のような弱い操作」）。primary はヒーローの 1 つだけに保つ。お休みの人は一覧の外に Tag「お休み」で出す。
- **これからの予定**：週ごとに Collapse の 1 行。見出しに日付（曜日つき）、Tag「予定」または「CT なし・祝日名」、ログイン中なら「あなた：〇〇さん」を出し、全ペアは開いたときだけ見せる（WTU:Collapse「複雑な領域を畳んでページを整理」、SP:stay「ページ遷移させない」）。先頭に「次のお休み」と「先の週は予定。増減で組み直し」を常に出す。
- **メンバー**：List は v6 で非推奨（`antd list` / `antd info List` で確認）のため Listy を使った。各行にアバター・名前・社員番号・uチャンネル・参加状態 Tag（参加＝チェックのアイコン＋「参加」、不参加＝マイナスのアイコン＋「不参加」）・初回設定未完了の Tag。自分の行には「設定を変える」、他人の行には danger の text ボタン「削除」。
- **削除の確認**：Modal。タイトルを「〇〇さんをメンバーから削除しますか？」にして誰を消すかを先に示し、本文で「元に戻せない」「参加中なら組み直しになる」を伝え、実行ボタンは danger の「削除する」（SP:buttons「否定的な主操作は結果を強調する」「Ask users the needed actions… then present the risks」）。Popconfirm ではなく Modal にしたのは、誰を・何が起きるかの説明が 1 行に収まらないため（WTU:Popconfirm は「簡素で小さな確認」）。モーダルを開いている間は背面を `inert` にした（自。antd の Modal は aria-modal は付けるが背面を inert にしない）。
- **自分の設定**：SP:research-form の設定テンプレート（7 項目未満はグループ化しない、提出して反映する型）。CT 参加は Switch ではなく Radio.Group（WTU:Switch「切り替えた瞬間に反映される操作」、WTU:Radio「選択肢を見比べられる」）。参加状況を変えた瞬間に、保存前の警告 Alert で「組み合わせから外れる／戻る」「全員分組み直し」「Slack に投稿済みの今週のペアとずれることがある」を出す（G5）。必須の印は「*」ではなく文字の「必須」（自。日本語のフォームで一般的な表記）。
- **はじめての設定**：同じフォームを流用。Steps は使わない（項目が 3 つで、SP:navigation の Steps は「2 より多く 5 未満の手順」向け。1 画面で終わる）。名前は Slack の表示名を入れておき、社員番号と uチャンネルだけを求める。完了したら組み合わせの画面に戻す。

## 5. 文言

SP:copywriting の原則のうち、日本語にも当てはまるものを使った。

- **利用者の立場で**：「あなたの相手」「あなたのペア」。システムを主語にしない。
- **一貫させる**：「ハドルを始める」「uチャンネル」「CT に参加する／参加しない」「組み合わせ」を全画面で同じ語にした。
- **重要な情報を目立つ位置に**：相手の名前を見出し（h2）にした。
- **完全に、直接**：エラーは「何が起きたか」＋「次に何をするか」の 2 文（例：「設定を保存できませんでした」＋「入力した内容はそのまま残っています。…もう一度『保存する』を押してください」）。利用者を責めない（「〜してください」で依頼する）。
- **不要な句読点を省く**：見出し・ラベル・入力欄の下の補足は句点なし。複数文の説明だけ句点を付ける。
- **感嘆符を使わない**。
- ボタンは動詞（「保存する」「削除する」「もう一度読み込む」）。既定の「OK／キャンセル」は使わない（SP:buttons）。

## 6. 決まっていないことの決め方（確定）

| 論点 | 決めたこと | 理由 |
| --- | --- | --- |
| どちらの uチャンネルでハドルを始めるか | ペアのうち**社員番号が大きい方**の uチャンネルに固定し、画面に「ハドルの場所：#u-xxx（2 人で共通）」と出す。どちらかが未設定なら導線を出さない | 2 人がそれぞれ「相手の」チャンネルで始めると別々の場所で待つことになる。場所を 1 つに決めて見せる。大きい方にしたのは、固定データのログイン者（id=1）から見て「相手の」チャンネルになるため（ブリーフの「相手の uチャンネル」と一致する） |
| 削除をログイン中の全員に許すか | 許す。ただし自分自身は削除できない（自分の行には「設定を変える」だけ） | ブリーフ「ログイン中の人はメンバーを削除できる」。自分を消すとログイン中の本人が宙に浮く。誤操作は確認モーダルで防ぐ |
| 先の週をどこまで見せるか | 固定データの全 5 週（今週＋4 週） | 「次のお休み」を確かめるには数週先まで要る。組み直しの可能性は「予定」Tag と注記で伝える |
| スマートフォン | 390px で G1・G2 を最初の画面（スクロールなし）で達成する。全画面 390px で横はみ出し 0 | 月曜の確認はスマートフォンからも想定される（推測） |
| 特定の人と次に当たる日 | 入れない | 主目的（今週の相手）から外れ、画面が増える。これからの予定の「あなた：〇〇さん」で代替できる |
| 参加者数の数え方 | 参加している人だけ（ホームの「参加者 9 人」）。メンバー画面では参加・不参加・初回設定未完了を別々に出す | 組み合わせに関係するのは参加者だけ。全体像はメンバー画面で補う |
| 社員番号の表示 | fixtures に社員番号が無いため、id を社員番号として表示する | データ上の仮定 |

## 7. 妥協点・ハーネスと違う判断

- **画面密度**：DM は「業務コンソール向けの高密度（14px 基準）」を前提にしている。このアプリは数十秒の確認が主なので、主役カードだけは見出しを大きく（h2＝20px）、ボタンを large・390px で横幅いっぱいにした。DM の数値（h1 38px など）はそのままでは 1 画面目を圧迫するため、見出しの token を 24/20/16px に下げた。
- **自前のスタイル**：CSS ファイルは書いていない（読み込んでいるのは antd 同梱の `antd/dist/reset.css` だけ）。`style` 属性は 19 か所あり、内訳は次のとおり。色・余白の量・線の太さはすべて token から読み、直接書いたのは配置のための値（`margin: 0` / `0 auto`、`flex`、`width: 100%`、`minWidth: 0`、`minHeight: 100vh`、`height: 100%`、`borderBottom: none`）だけ。
  - 見出し・段落の `margin: 0`（10 か所）：Typography の既定の下余白を消し、Flex の gap だけで間隔を揃えるため。
  - アバターの背景・文字色（1 か所）：公式デモ（`antd demo Listy rich`）と同じ方法。色は token の `blue1`/`blue8` など。
  - レイアウト（8 か所）：本文の最大幅・余白（Layout.Content に該当 token が無い）、ヘッダー下の境界線（Layout.Header に該当 token が無い）、390px 用の 2 段ヘッダーの余白、横並び Menu を伸ばして「…」に畳まれないようにする `flex: 1`。
- **S10 の message を消さない**：撮影のための例外（状態指定時のみ）。
- **S14 の失敗は固定**：デモでは「もう一度削除する」を押しても失敗のまま（S14 の再現を優先）。S17 は再度押すと成功する。
- **組み合わせの再計算はしない**：参加状況を変えても固定データのペアは変わらない。代わりに主役カードで「参加していないため相手はいません」「まだ今週の組み合わせに入っていません（組み直し中）」を出す。
