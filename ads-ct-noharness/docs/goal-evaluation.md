# 目標の自己評価（ハーネスなし版）

## 評価の方法

1. **論証**：目標ごとに「目標 → 意図 → 画面の要素 → 証拠」をたどる。証拠は `screenshots/` の画像と、下記の計測・検査の結果。
2. **計測（G1・G2）**：Playwright で S01 を開き、相手の名前とハドルのボタンの位置、スクロール量、操作回数を測った（スクリプトは自作。リポジトリには入れていない）。
   - 1440×900 と 390×844（スマートフォン相当）。撮影スクリプトの 390×900 でも結果は同じ（ボタンは 900px より上）。
3. **共通の検査**：`scripts/capture.mjs`（`brief/scripts/capture.mjs` の写し。ESM の import が実行ファイルの場所から解決されるため、`@axe-core/playwright` を入れたこのフォルダに写して実行）で、18 状態 × 2 幅 = 36 件の axe（WCAG 2.1 AA）と横はみ出しを検査。結果は `screenshots/report.json`。
4. **操作の確認**：ハドル開始、未ログイン → ログイン、削除（成功）、参加の変更と警告、保存、初回設定の未入力送信を Playwright で実際に操作して確かめた。

## 目標ごとの論証

### G1 開いてすぐ「今週、自分は誰と話すか」がわかる — 達成と判断

- 意図：一覧から自分を探させない。開いた瞬間の視界に答えを置く。
- 要素：トップの見出し直下に「今週のあなたの相手」カード（青い枠＋影）。xlarge のアバターと xlarge の見出しで「高橋 健太 さん」、その上に「2026年10月5日（月）14:00 から」。
- 証拠：`S01-1440.png`・`S01-390.png`。名前の下端は 381px／433px で、スクロールなしで見える。
- 例外の状態：お休み（`S03`）は同じ場所に「今週、あなたはお休みです」と次の相手、参加者 2 人未満（`S05`）はカードを出さず警告。

### G2 その相手との通話をすぐ始められる — 達成と判断

- 意図：相手を確かめた視線の続きに、迷わない 1 つのボタン。
- 要素：カード内の、画面で唯一の主ボタン「#u-kenta でハドルを始める」と「ペアの 2 人とも #u-kenta に集まります」。ペアごとに集まる場所を 1 つに決めた（社員番号が後ろの人の uチャンネル）。
- 証拠：計測で 1 回の操作、スクロール 0。`S09` では相手の uチャンネルが未設定なのでボタンを出さず、「Slack の DM で声をかけて」と代わりの手段を示す。
- 弱いところ：集まる場所のルール（後ろの人の uチャンネル）を相手側が知らないと、相手が自分の uチャンネルで待つ可能性がある。相手の画面でも同じチャンネル名が出るので一致はするが、ユーザーテストはしていない。

### G3 先の週の予定を確かめられる — 達成と判断

- 意図：「来週は誰か」「次にお休みはいつか」は自分の問いなので、自分の分だけを抜き出す。
- 要素：カード内の「あなたの今後の予定」（10月12日 CT なし（スポーツの日）、10月19日 鈴木 翔太 さん…）と「表示している期間に、あなたのお休みはありません」。下には全員の各週を縦に並べ、来週以降は「予定」ロゼンジ＋見出し下の説明。
- 証拠：`S01`・`S03`（id=9 は今週お休み、次の CT と相手を本文で示す）・`S04`（祝日の週）。
- 弱いところ：「特定の人と次に当たる日」は検索を作らず、5 週分の一覧から目で探す形。

### G4 誰が組み合わせに入っているかを確かめ、いなくなった人を安全に外せる — 達成と判断

- 意図：参加／不参加を色以外でも区別。削除は「誰を」を名指しして確認し、失敗してもやり直せる。
- 要素：メンバー画面の社員番号順のリスト、「参加」「不参加」「初回設定が未完了」の文字つきロゼンジ、「参加 9 人・不参加 2 人（全 11 人）」。削除はモーダル（タイトルに名前、危険の見た目、初期フォーカスは「キャンセル」）、成功はフラグ、失敗はモーダル内のエラーと「もう一度削除する」。
- 証拠：`S11`・`S13`・`S14`。操作確認で、初期フォーカスが「キャンセル」、削除後にフラグが出て 11 → 10 行になった。
- 弱いところ：自分自身は削除できない（設計上の判断）。権限の制限はない（全ログイン者が削除可）。

### G5 参加状況を変えられ、その影響が伝わる — 達成と判断

- 意図：影響は保存の前に伝える。
- 要素：「参加する／参加しない（休職・繁忙期など）」のラジオ。今と違う値を選んだ瞬間に、すぐ下へ警告「保存すると、全員の組み合わせが組み直されます」。保存後はフラグで「全員の組み合わせが組み直されます」と再度伝える。
- 証拠：操作確認で警告とフラグの表示を確認。`S10`（保存直後のフラグ）、`S17`（保存失敗。入力は残り、もう一度押せる）。
- 弱いところ：警告が出た状態の静止画は状態一覧に無い（S01〜S18 に含まれないため撮っていない）。

### G6 初めての人が迷わず必要な設定を終えられる — おおむね達成と判断

- 意図：必須だけを聞き、未入力ならどこが足りないかをまとめて示す。
- 要素：「はじめての設定」画面（名前は Slack の表示名で埋まっている、社員番号、uチャンネル、参加は「参加する」が初期値）。必須は * と「* は必須の項目です」。未入力で送ると、上にまとめ（フォーカスを移す）、各項目の下にエラー文。設定が済むまで他の画面の上部に「はじめての設定が終わっていません」。
- 証拠：`S15`・`S16`。操作確認で、まとめへのフォーカス移動を確認。
- 弱いところ：初回ログイン直後に自動で設定画面へ移す処理は入れていない（デモでは `/setup?as=11` で開く。他の画面には案内を出す）。

### G7 どんな状態でも、何が起きていて次に何をすればよいかがわかる — 達成と判断

| 状態 | 何が起きたか | 次の行動 |
| --- | --- | --- |
| S06 読み込み中 | スピナー＋「組み合わせを読み込んでいます…」（role=status） | 待つ |
| S07 読み込み失敗 | エラーのセクションメッセージ | 「もう一度読み込む」、Slack の投稿でも確認できる旨 |
| S08 ログイン失敗 | エラーのセクションメッセージ（組み合わせは見られる） | 「もう一度 Slack でログイン」 |
| S05 参加者 2 人未満 | 警告のセクションメッセージ | 「メンバーを確認する」 |
| S12 メンバー 0 人 | 空の状態（EmptyState） | 「Slack でログイン」 |
| S14 削除失敗 | モーダル内のエラー | 「もう一度削除する」 |
| S17 保存失敗 | フォーム上部のエラー（入力は残る） | 「保存する」をもう一度 |
| S18 404 | 空の状態とアクセスした URL | 「組み合わせに戻る」 |

## 評価の限界

- **自己評価である。** 作った本人が、作った意図に沿って論証している。利用者による検証（ユーザーテスト）はしていない。
- 計測は理想的な条件（ページの読み込みは即時、固定データ）。実際の通信時間や Slack の認可は含まない。
- 「迷わず」「すぐ」は操作回数とスクロール量で代用しており、理解のしやすさそのものは測っていない。
- axe は自動で検出できる範囲だけ。スクリーンリーダーでの実機確認はしていない。事後計測の lint では、axe が見つけない ADS 固有の指摘が 14 件出た（`docs/post-hoc-lint.md`）。
- ADS としての「らしさ」は、私の事前知識と型定義だけで判断しており、公式のガイドラインとの照合はしていない（実験の条件）。
