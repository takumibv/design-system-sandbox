# 設計判断（ハーネスなし版）

> 対照実験の条件：ADS の AI 向けハーネス（llms.txt・ads-cli・ADS MCP・atlassian.design の文書・公式 lint）を使わずに決めた。
> 判断材料は `brief/`、`node_modules/@atlaskit/*` の型定義（`.d.ts`）と同梱 README、自分の事前知識だけ。
> パッケージ内の `constellation/` フォルダ（docs サイトの原稿と思われる）は「公式ドキュメント」に当たると判断し、開いていない。

この文書は **画面構成を決める前の下書き** として書き始め、実装中に変わった点は「実装後の追記」に残す。

## 0. 前提として決めたこと

- 利用の中心は「月曜の CT 直前に数十秒だけ開く」。だから**トップ画面の最初の 1 画面で G1・G2 が完結すること**を最優先にする。他の目標（G3〜G6）は頻度が低いので、トップの下側や別画面に回してよい。
- 390px（スマートフォン）でも G1・G2 はスクロールなしで完結させる。Slack の投稿リンクはスマートフォンから開かれる可能性が高い（推測）。
- 画面は「組み合わせ（トップ）」「メンバー」「自分の設定」の 3 つ＋ 404。初回設定は「自分の設定」と同じフォームを別の見出し・説明で出す（入力項目が同じなので、別画面にすると保守が二重になる）。

## 1. 目標ごとの達成手段（下書き）

| 目標 | どの画面・要素で | 判断の根拠 |
| --- | --- | --- |
| G1 今週の相手がすぐわかる | トップの一番上に「今週のあなたの相手」カード。大きいアバター＋名前＋日時（10月5日（月）14:00〜）。全員のペア一覧より前に置く | 「滞在は数十秒」「探さずにわかる」（ブリーフ）。一覧の中で自分を探させると G1 の時間が伸びる |
| G2 すぐ通話を始める | 同じカードの中に、画面で唯一の主ボタン「u-kenta でハドルを始める」 | 相手を確かめた直後の視線の位置に置く。主ボタンを 1 つに絞れば迷わない（一般的な UI の知識＋ ADS の「primary は 1 画面 1 つ」という事前知識） |
| G3 先の週の予定 | ①カード内に「あなたの今後の予定」（週ごとの相手／CT なし／お休み）を小さく並べる ②トップ下部に全週のペア一覧を縦に並べ、来週以降に「予定」ロゼンジ | 「来週は誰か」「次にお休みはいつか」は自分に関する問いなので、全員の一覧から探させず自分の行だけ抜き出す |
| G4 メンバーの確認と安全な削除 | 「メンバー」画面：社員番号順のリスト、参加／不参加は文字つきロゼンジ、削除は確認モーダル（危険ボタン）→ 結果をフラグで通知、失敗はモーダル内に表示 | 取り消せない操作は「誰を」を名指しして確認する（ブリーフ）。失敗時はモーダルを閉じずにやり直せるようにする |
| G5 参加状況の変更と影響 | 「自分の設定」：参加する／参加しない をラジオで選ぶ。現在と違う値を選んだ瞬間に、すぐ下に「保存すると〜組み直されます」と出す。保存後はフラグで再度伝える | 影響は「変える前」に伝えないと意味がない（一般的な UI の知識） |
| G6 初回設定 | 初回ログイン時は「はじめての設定」画面へ移す。必須に * をつけ、未入力で送るとフィールドの下にエラー＋先頭にまとめ。設定が済むまで他の画面にも案内を出す | 必須項目が埋まるまで入力を求める（ブリーフ） |
| G7 状態ごとの説明と次の行動 | 読み込み中＝スピナー＋文言、失敗＝セクションメッセージ（エラー）＋「もう一度読み込む」、空＝空の状態（EmptyState）＋次の行動、404＝EmptyState＋「組み合わせに戻る」 | 各状態で「何が起きたか」と「次に押すもの」を必ず 1 つ以上置く |

## 2. 画面構成（下書き）

- 全体の枠：`@atlaskit/navigation-system` の `Root` / `TopNav` / `SideNav` / `Main`。
  - 上部：サイドナビ開閉ボタン、Gaji-Labo のロゴ（別タブで https://www.gaji.jp/）、「CTスケジュール」の表題、右端にログイン（未ログイン）またはプロフィール（ログイン中。メニューに名前とログアウト）。
  - 左：サイドナビ「組み合わせ」「メンバー」「自分の設定」。現在地は選択状態。下部にログイン中の自分（アバター＋名前）。
  - 型定義で `@atlaskit/atlassian-navigation` に `@deprecated ... Use @atlaskit/navigation-system instead` とあったため、こちらを採用（型定義・README 由来）。
- トップ（組み合わせ）
  1. 見出し「CT の組み合わせ」＋「毎週月曜 14:00 から／参加者 9 人（メンバーを見る）」
  2. 今週のあなたの相手（ログイン中）／ログインの案内（未ログイン）
  3. 今週のペア一覧（自分のペアは背景色＋「あなた」ロゼンジ）
  4. 来週以降（予定）の各週を縦に並べる
- メンバー：見出し＋人数のまとめ＋リスト（表ではなくリスト。390px で横はみ出しを起こさないため）
- 自分の設定／はじめての設定：`@atlaskit/form` のフォーム 1 枚

## 3. 決まっていないことへの答え（下書き）

- ハドルの場所：**ペアごとに 1 か所**に決める。社員番号が後ろの人の uチャンネル。1 番の自分から見ると常に「相手の uチャンネル」になる。2 人が別々の場所で同時にハドルを始めてすれ違う事故を防ぐため。どちらかの uチャンネルが未設定のペアでは、ブリーフどおりボタンを出さず、理由と代わりの手段（Slack の DM）を書く。
- 削除の権限：ログイン中の全員に許す（ブリーフの機能要件どおり）。ただし**自分自身は削除できない**（自分を消すとログイン中の人が一覧からいなくなる。自分が抜けたいときは「参加しない」を使う）。
- 先の週の範囲：固定データの 5 週（今週＋4 週、約 1 か月）。それ以上は組み直しの可能性が高く、予定としての価値が下がる。
- 特定の人と次に当たる日：検索機能は入れない。代わりに「あなたの今後の予定」で自分の相手を週ごとに並べる（頻度が低く、5 週の範囲なら一覧で足りる）。
- 参加者数：**参加している人だけ**を「参加者」と数え、メンバー画面では「参加 9 人・不参加 2 人（全 11 人）」と両方出す。
- スマートフォン：G1・G2（トップの最初の 1 画面）を 390px で完結させる。メンバー・設定も 390px で操作できるようにするが、最適化はトップほどしない。
