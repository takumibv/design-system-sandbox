# 目標の自己評価（ハーネスなし版）

## 評価の方法

1. **論証**：目標ごとに「目標 → 意図 → 画面の要素 → 証拠」をたどる。証拠は `screenshots/` の撮影（1440px／390px、高さ 900px のビューポート）と、Playwright で実際に操作して確かめた結果。
2. **計測（G1・G2）**：Playwright（プリインストール版）で S01 を開き、要素の位置（`boundingBox`）とスクロール量（`scrollY`）、必要な操作の回数を数えた。ビューポートは 1440×900 と 390×900。
3. **共通の検査**：`scripts/capture.mjs`（ブリーフの撮影スクリプトの複写）で axe（wcag2a/2aa/21aa）と横はみ出しを全 18 状態 × 2 幅で検査。
4. 実際の利用者による評価はしていない（下の「評価の限界」）。

## 計測結果（G1・G2）

| 項目 | 1440px | 390px |
| --- | --- | --- |
| 相手の名前の位置（上端 y） | 309px | 336px |
| 相手を知るまでの操作 | 0 回（開くだけ） | 0 回 |
| 相手を知るまでのスクロール | 0px | 0px |
| 「ハドルを始める」の位置（下端 y） | 342px | 454px |
| ハドル開始までの操作 | 1 回（主ボタンを押す） | 1 回 |
| ハドル開始までのスクロール | 0px | 0px |
| お休みの週（S03）の「今週、あなたはお休みです」（上端 y） | 256px | 288px |
| 未ログイン（S02）から相手を知るまで | 1 回（「Slack でログイン」）※デモでは id=1 としてログイン | 同じ |

すべて 900px のビューポートの 1 画面目に収まる。

## 共通の検査の結果

- axe（WCAG 2.1 AA）：最終版で全 36 枚とも違反 0。途中で `link-in-text-block`（灰色の文中の「メンバーを見る」リンク）が出たため、リンクを文から出して並べた。
- 横はみ出し：最終版で全 36 枚とも 0px。途中で 390px で 182px（ナビ）と 45px（未ログイン時のナビ）はみ出したため、`Scroller` で包み、mobile ではナビのラベルとアイコンを外した。
- 結果の生データ：`screenshots/report.json`。

## 目標ごとの論証

### G1 開いてすぐ「今週、自分は誰と話すか」がわかる — 達成（計測で確認）
- 意図：滞在数十秒・目的 1 つなので、探させず、読む前に目に入る位置と大きさにする。
- 要素：ページ見出し直下の `Base`（layer=1、影つき）に「今週 2026年10月5日（月）14:00〜」「今週のあなたの相手」と、56px のアバター＋ XXL 太字の「高橋 健太 さん」。画面内でいちばん大きい文字。
- 証拠：`S01-1440.png`、`S01-390.png`。上の計測で操作 0 回・スクロール 0。お休みの週は同じ位置に「今週、あなたはお休みです」と次回の相手（`S03-*.png`）。

### G2 その相手との通話をすぐ始められる — 達成（計測で確認）
- 意図：相手の名前の隣に唯一の primary ボタン。どのチャンネルで始まるかを明記して迷わせない。
- 要素：「ハドルを始める」（primary、画面で 1 つ）＋「#u-kenta で始まります」。ペア一覧のハドルボタンは secondary で小さく。
- 証拠：計測で 1 クリック・スクロール 0。押すとページ上部の `NotificationBar` に「（デモ）Slack の #u-kenta でハドルを始めます。」（ライブリージョンでも読み上げ）。相手の uチャンネルが無い S09 では、ボタンの代わりに warning で理由と代わりの行動（`S09-*.png`）。
- 弱い点：ボタンを押した結果はデモ通知で、実際の Slack 連携は未実装。

### G3 先の週の予定を確かめられる — おおむね達成
- 意図：来週以降を縦に並べ、開かなくても「その週の自分の相手」がわかるようにする。予定であることを文と見た目で伝える。
- 要素：「これからの予定」に 4 週分の `AccordionPanel`。閉じた状態で「日付（月）」「予定」ラベル（祝日は「CT なし」）「あなたの相手：○○さん」。冒頭に「来週以降の組み合わせは予定です。参加者が…組み直されます」と「あなたの次のお休み：…」。
- 証拠：`S01-*.png`、`S04-*.png`（`?week=2026-10-12` で祝日の週を開いた状態）。
- 弱い点：全ペアを見るには開く操作が要る。範囲は fixtures の 5 週（今週＋4 週）に固定。id=1 は期間内にお休みが無く「表示中の期間にはありません」となるので、お休みの表示はこの id では検証できていない（S03 の id=9 では今週がお休み）。

### G4 誰が組み合わせに入っているかを確かめ、いなくなった人を安全に外せる — 達成
- 要素：メンバー画面（社員番号順）。「参加 9 人・不参加 2 人」。各行に `StatusLabel`「参加」（緑）／「不参加」（灰）、未完了は「初回設定が未完了」（警告色）。文字で区別しているので色だけに頼らない。削除は secondary の小ボタン → `ControlledActionDialog`（見出し「加藤 大輔さんを削除しますか？」、本文で取り消せないことと組み合わせへの影響、danger の「削除」、「キャンセル」）。
- 証拠：`S11`〜`S14`。Playwright で削除を実行し、行が 11→10 になり成功の `NotificationBar` が出ることを確認。失敗（S14）はダイアログ内にエラーを出し、そのまま再試行できる。
- 弱い点：初期フォーカスはキャンセルではなくダイアログ先頭（部品の既定）。

### G5 自分の参加状況を変えられ、その影響が伝わる — 達成
- 要素：「CT への参加」の `Fieldset` に常時の補足、`Checkbox`「CT に参加する」、チェックを外した時点で warning の `InformationPanel`「保存すると、全員の組み合わせが変わります／参加者が 9 人から 8 人になり…」。保存後は success の通知。
- 証拠：Playwright でチェックを外すと warning が表示され、保存で「設定を保存しました。」を確認。`S10`、`S17`。

### G6 初めての人が迷わず必要な設定を終えられる — 達成（ただし単独の利用者テストなし）
- 要素：専用画面 `/setup`。名前は Slack の表示名を初期値、必須 3 項目に「必須」、何に使うかの補足、uチャンネルは一覧から選ぶ。送信時の不足はページ上部のまとめ（フォーカス移動）と各項目の下に出す。他の画面では上部に「初回設定へ進む」。
- 証拠：`S15`、`S16`。Playwright で空送信 → まとめにフォーカス → 入力して送信 → `/` に戻り「初回設定が終わりました。」を確認。

### G7 どんな状態でも何が起きていて次に何をすればよいかがわかる — 達成
- 各状態の画面と次の行動：S06 `Loader`「組み合わせを読み込んでいます…」／S07「組み合わせを読み込めませんでした」＋「再読み込み」／S08 error 通知＋「もう一度ログイン」／S05「参加している人が 2 人未満」＋メンバーへのリンク／S12「まだメンバーがいません」＋ログイン／S17 error 通知（入力は残る）／S18「ページが見つかりません」＋「組み合わせへ戻る」。
- 証拠：該当する `screenshots/S*-*.png`。

## 評価の限界

- 評価者は作った本人（この版のモデル）で、利用者による検証はしていない。「迷わず」「すぐ」は位置と操作回数での代理指標。
- 計測は固定データ・高さ 900px で、実際の端末の高さやフォントの違いは見ていない。
- axe は自動で見つかる問題だけを見る。スクリーンリーダーでの実操作、キーボードだけの通し操作は一部（ダイアログの初期フォーカス、送信エラー時のフォーカス）しか確かめていない。
- SmartHR Design System のガイドラインに合っているかは、事前知識の範囲でしか判断していない。どこが合っていないかは `post-hoc-lint.md`（事後計測）と、ハーネスあり版との比較で見る。
