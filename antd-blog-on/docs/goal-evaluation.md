# 目標の評価

## 1. 評価の方法（基準とその理由）

実際の利用者による検証はできないので、**「目標 → 意図 → 画面の要素 → 証拠」の論証**で評価する。証拠として使えるのは次の 4 種類だけで、それぞれの限界を明記する。

| 基準 | 何を確かめるか | 理由 |
| --- | --- | --- |
| A. 到達の手数 | 目標に関わる情報に、最初の画面から何操作で着くか（0 操作＝開いた瞬間に見える） | 利用頻度が低い（週 1・月数回）ので、探さずに見えることが「忘れない」「早く気づく」に直結する。`spec/research-workbench.md` 9行「重要情報への経路を短く」 |
| B. 固定データでの正しさ | 2026-11-09 の固定データで、遅れ（id=6）・空き週（11/23・12/21・12/28 の週）・予定の無い人（中村 彩・加藤 大輔）・自分の担当（佐藤 美咲：id=7・14）が正しく出るか | 「分かる」という要件は、正しく数えられて初めて満たされる |
| C. 色に頼らない | 遅れ・空き週が文で書かれているか、色覚や読み上げでも伝わるか | design.md 299行「点は文字の代わりにならない」。WCAG 1.4.1 |
| D. 自動検査 | axe（WCAG 2.1 AA）違反 0、横はみ出し 0、公式 lint 0、1440／390 の両方 | ブリーフの検査条件。客観的に再現できる唯一の証拠 |

## 2. 目標ごとの論証

### O1 週 1 本以上のペースで途切れずに公開し続ける
- **意図**：途切れ（空き週）が起きる前に、空いている週を見つけて埋める。
- **画面の要素**：計画（`/`）の「週ごとの計画」で 1 週＝1 項目、見出しに「✓ 2 本予定」／「⚠ 予定がありません」、赤い点、破線ボタン「この週に予定を入れる」（押すとその週の月曜を公開予定日にした登録ドロワー）。上部 Alert に「今週から 8 週間で予定の無い週が 3 週（11/23・12/21・12/28 の週）」。下段に空き週を埋める候補「日付未定のアイデア」。
- **証拠**：
  - A：空き週は 0 操作（開いた画面の Alert と計画に見える）。埋めるのは 1 操作でドロワーが開く（S41：`/?new=1&date=2026-11-23&as=editor` で予定日入りのドロワー）。
  - B：11/23 の週は「年末イベントの告知」（取りやめ）だけ。取りやめを数えず「予定がありません」と出し、「取りやめの投稿は本数に数えていません」と注記（S01・S03 のスクリーンショット）。12/21・12/28 の週も空きとして出る。
  - C：「予定がありません」の文＋アイコン。点の色は補助。
  - D：下の「自動検査の結果」参照。
- **評価**：空き週の「発見」と「その場で埋め始める」までは満たす。実際に週 1 本の公開が続くかは、人が書くかどうかに依存し、画面では保証できない。

### O2 書く人や時期の偏りを減らす
- **意図**：書いていない人・偏っている人を数で見せ、次の依頼先を選べるようにする。
- **画面の要素**：書く人（`/members`）の表（公開済み・予定・遅れ・次の予定日・最後の公開日、並べ替え可）、要約「期間内に公開した人 N / 10 人」「期間内の公開・予定がない人 N 人（名前）」。時期の偏りは計画で週ごとの本数（今週 2 本・空き週 0 本）が並ぶこと。
- **証拠**：
  - A：計画から 1 操作（上部ナビ「書く人」）。
  - B：既定期間（10/1〜12/31）で、公開した人は 田中 遥・伊藤 葵・佐藤 美咲・小林 結衣 の 4 人（id=1・3・5・7。id=3 と 5 は 2 本ずつ）。予定も公開も無い人として 中村 彩・加藤 大輔 が要約に名前で出る（S20）。
  - C：数は数字と「本」「件」で書く。
- **評価**：偏りを「見える」ようにはした。偏りを「減らす」のは編集担当の行動次第。カテゴリの偏りは扱っていない（ブリーフは書く人と時期の偏りだけを挙げているため）。

### O3 書く人が、自分の担当と予定日を忘れない
- **意図**：開いた瞬間に自分の分と「あと何日」「何日過ぎた」が見える。
- **画面の要素**：計画の右列「あなたの担当」（公開前を予定日順、「あと 3 日」）。390px では計画より上に出す。名前に「（あなた）」。投稿一覧の「自分の担当だけ」（`/posts?mine=1`）。詳細で自分の投稿は「編集」「状態を変更」ができる。
- **証拠**：
  - A：0 操作（S01、390px でも 1 画面目、S01-390）。
  - B：佐藤 美咲（id=1）には「アクセシビリティ改善の振り返り（11/12、あと 3 日）」と「（仮）型安全な API クライアント（未定）」が出る。公開済みの「新メンバー受け入れの 1 か月」は出さない。
  - C：「あと 3 日」「予定日を 4 日過ぎています」と文で出す。
- **評価**：アプリを開けば忘れない。ただし「開かないと気づかない」。Slack 通知（予定日の前日に知らせる等）はブリーフで「デモでは通知を出すだけでよい」とされたログイン以外は範囲外で、O3 の効果の大半は通知に依存すると推測する（推測）。

### O4 編集担当が、計画の抜けや遅れに早く気づける
- **意図**：週 1 回開いたときに、遅れと抜けが最上部にまとまって見え、そのまま次の行動（詳細を開く・一覧で見る・予定を入れる）に移れる。
- **画面の要素**：計画上部の warning Alert（遅れ件数・空き週・「遅れを一覧で見る」）。編集担当だけの「要対応」（予定日を過ぎた投稿／2 週間以内なのにアイデアのまま／予定の無い週＋「予定を入れる」）。各行の「予定日を N 日過ぎています」。書く人の表の「遅れ」列。
- **証拠**：
  - A：0 操作（S03）。遅れの一覧は 1 操作（S14：`/posts?overdue=1&undated=0` に「テストの書き方ガイドライン（仮）」1 件）。
  - B：id=6（予定 11/5、執筆中）が「予定日を 4 日過ぎています」と出る。公開済みの id=2（予定 10/12・公開 10/14）は遅れに数えない。
  - C：Alert は文、行は文＋アイコン。Tag で遅れを表していない（design.md 297行）。
- **評価**：気づくまでは満たす。遅れた本人への声かけ（Slack への導線）は画面に無い。

## 3. 自動検査の結果

- 公式 lint：`npx antd lint ./src` → **No issues found**（初回 2 件の deprecated を修正）。
- axe（WCAG 2.1 AA）・横はみ出し：`screenshots/report.json`（45 状態 × 1440／390 = 90 件）。結果は README の「検査結果」に転記。
  - 初回（既定トークン）：color-contrast 違反がほぼ全状態（S01-1440 で 58 件）。登録ドロワーで横はみ出し 8px（body の既定 margin）。`harness-logs/14-capture-first-report.json`。
  - 修正：既定パレットの濃い段へトークンで寄せ、Tag の色を替え、`antd/dist/reset.css` を読み込んだ。

## 4. 評価の限界

- 利用者による検証（タスク達成・時間・誤り）はしていない。上の論証は設計者自身によるもので、主役の選び方が正しいかは確かめていない。
- 固定データ 15 件・10 人だけで確かめた。投稿が 100 件・書く人 50 人の規模で、計画のタイムラインや要対応が読みやすいままかは分からない。
- 「目標の達成」（実際に週 1 本続く、偏りが減る）は運用の結果であり、画面だけでは評価できない。ここで評価したのは「気づける・分かる」までの段階。
- axe は自動で判定できる項目だけを見る。キーボード操作の順序、読み上げでの分かりやすさ、Timeline の読み上げ順は手で確かめていない。
- 状態の再現は URL のクエリで作った見かけの状態（`flash`・`preview` 等）を含む。実際の通信失敗の挙動は `fail=` で疑似的に再現しただけ。
