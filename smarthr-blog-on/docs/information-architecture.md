## 1. ユーザーの業務の説明

ハーネスは目的を「登場人物を特定すること」「主要なユースケースを特定すること」とする［H］`ia/user-operations-description.mdx.txt:17-18`。書式は自由で「ユーザーごとのタスクを箇条書きしたもの」でもよい［H］同 `:29`。ここではその形で書く。

### 登場人物

| 登場人物 | ブリーフ上の役割 | 人数（固定データ） | 根拠 |
| --- | --- | --- | --- |
| 取りまとめ役 | 編集担当（`role: editor`） | 1 人（id=2 高橋 健太） | ［B］「依頼者：社内ブログの取りまとめ役」「編集担当は、すべての投稿予定を編集・削除できる」 |
| 書く人 | 一般メンバー（ログイン中） | 9 人 | ［B］「ログイン中の人は、投稿予定を登録し、自分が書く人に入っている投稿を編集できる」 |
| 読む人 | 未ログイン | 不明 | ［B］「ログインしていなくても閲覧はできる」 |

### 利用場面の仮定（すべて［仮定］）

| 登場人物 | いつ・どのくらい | 何のために開くか |
| --- | --- | --- |
| 取りまとめ役 | **週 1 回**（週の始め、月曜の午前）。加えて Slack で「公開しました」と言われたとき | ① 今週の公開予定が動いているか ② **予定日を過ぎた投稿**が無いか ③ この先数週間に**予定の無い週**が無いか ④ 書く人が**一部の人に偏っていないか**を見て、Slack で声をかける。公開された投稿を「公開済み」にして URL を記録する（書く人の代わりに行うこともある） |
| 書く人 | **月に数回**。Slack の通知（デモでは通知の表示のみ）や、思いついたとき | ① **自分の担当と予定日**を確認する ② 状態を進める（執筆中 → レビュー中 → 公開済み） ③ アイデアを登録する。主にパソコン、移動中にスマートフォンで予定日だけ確認することもある |
| 読む人 | まれ | 次に何が公開されるかを眺める。操作はしない |

**最も頻度が高いのは書く人、最も業務上の判断が多いのは取りまとめ役**と置いた。ブリーフの目標 4 つのうち 3 つ（O1・O2・O4）は取りまとめ役の判断、1 つ（O3）は書く人の記憶に関わる［B］。

### 主要なユースケース

1. 取りまとめ役が、今週以降の予定を週ごとに見て、予定の無い週と遅れを見つける（O1・O4）
2. 取りまとめ役が、書く人ごとの予定と実績を見て、まだ書いていない人・予定の無い人に声をかける（O2）
3. 書く人が、自分の担当を予定日の近い順に見て、遅れていないか確かめる（O3）
4. 書く人・取りまとめ役が、投稿を追加し、状態を進め、公開したら公開日と URL を記録する（機能要件）
5. 取りまとめ役が、不要になった投稿を取りやめ、または削除する（機能要件）

## 2. 概念モデル

ハーネスの指示：「既存のDBの構造や、機能への要望をそのまま描き起こすことは期待されません」［H］`ia/conceptual-model.mdx.txt:29`。概念は「オブジェクトに限らない、業務上重要な概念（プロパティ・プロセス・ナビゲーションなどを含む）」［H］同 `:54`。

```
[メンバー]  ── 書く（1 : 0..n）──▶  [投稿]  ── 属する（n : 1）──▶  [週]
  役割：一般メンバー／編集担当          状態：アイデア／執筆中／レビュー中／公開済み／取りやめ
                                          カテゴリ：技術／デザイン／チーム・文化／イベント報告
                                          公開予定日・公開日
```

### ハーネスの観点で直したこと

| ブリーフの言葉 | 観点 | 概念モデルでの扱い |
| --- | --- | --- |
| 「投稿予定」と「公開済みの投稿」 | 「名前の末尾に同じ言葉を持つ概念が複数ないか」…「1つの概念にまとめ」［H］`ia/conceptual-model.mdx.txt:130` | **「投稿」1 つにまとめ、予定か実績かは「状態」で区別する**。予定も実績も同じものの時期違いだから |
| 「自分の担当」「自分が書く投稿」 | 「『〇〇の▢▢』といった概念が登場していないか」［H］同 `:127` | 概念にしない。「メンバー」と「投稿」の関係（書く人）を、ログイン中のメンバーで絞ったもの |
| 「投稿予定が入っていない週」 | 同上 | 概念「週」と「投稿」の関係が 0 件である状態。独立した概念にしない |
| 「遅れ」（予定日を過ぎても公開されない） | 「動作を表す言葉が概念として登場していないか」［H］同 `:128` | 概念にしない。投稿の状態（公開済み・取りやめ以外）と公開予定日、今日の日付から決まる**投稿の性質** |
| 「週」 | 業務上重要な概念か［H］同 `:71` | **概念に入れる**。目標 O1 が「週 1 本以上」と週を単位にしているため［B］ |

## 3. オブジェクトモデル

オブジェクトモデルは「UIの骨格（何を見せ、何を操作できるべきか）を検討・レビューするのに向きます」［H］`ia/object-model.mdx.txt:11`。

```
┌───────────────────────┐            ┌─────────────────────────┐
│ 投稿                   │ 1..n : 0..n │ メンバー                  │
├───────────────────────┤ ◀┄┄┄┄┄┄┄┄┄┄ ├─────────────────────────┤
│ タイトル（仮タイトル可） │   書く人     │ 名前                      │
│ カテゴリ                │  （参照）     │ 役割（一般メンバー／編集担当）│
│ 書く人（メンバー 1 人以上）│             │ ─ 以下は投稿から求める値 ─   │
│ 公開予定日（未定可）      │             │ 公開済みの本数              │
│ ステータス               │             │ これからの予定の本数         │
│ 公開日                  │             │ 最後に公開した日            │
│ 記事 URL                │             │ 次の公開予定日              │
│ メモ                    │             ├─────────────────────────┤
├───────────────────────┤             │ （このアプリでの操作は無し）  │
│ 追加                    │             └─────────────────────────┘
│ 編集                    │
│ ステータスの変更          │
│ 公開済みにする（公開日・URL）│
│ 取りやめる               │
│ 削除                    │
└───────────────────────┘
```

| 判断 | 根拠 |
| --- | --- |
| **「週」はオブジェクトにしない**。投稿の公開予定日（または公開日）から決まる、ビューのまとまりの単位として使う | 「文字列や数値や日付をオブジェクトとしていないか」…「『期間』『年度』…はプロパティとして扱います」［H］`ia/object-model.mdx.txt:109`。概念モデルでは週を重要概念に置いたが、操作の対象ではないため |
| **「計画」「スケジュール」「一覧」をオブジェクトにしない** | 「『図』『表』『一覧』といった画面上のレイアウト（ビュー）を示す言葉がオブジェクトに登場する場合、…見落とされている可能性」［H］同 `:108` |
| 「取りやめる」「公開済みにする」をアクションとして明記 | CRUD と粒度の異なるアクションも図に示す［H］同 `:46`、「アクションに不足はないか」［H］同 `:131` |
| メンバーは操作を持たないが、オブジェクトとして残す | 観点 #1「プロパティやアクションを持たない場合…他のオブジェクトのプロパティである可能性」［H］同 `:107` に**あえて従わない**。理由：目標 O2（書く人の偏り）は「メンバーごと」に見て比べることが主目的で、メンバーを並べるビューが要る［判断］。メンバー管理（追加・役割変更）はブリーフの範囲外［B］ |
| ステータスの見出しは「ステータス」と書く（「状態」と書かない） | 「テーブルのヘッダー部分は`ステータス`と表記します」「`状況`や`状態`と表記すると、何の状況や状態を指すのかが曖昧なため避けましょう」［H］`patterns/smarthr-table.mdx.txt:203-205`。ブリーフの「状態」とは表記が変わる |

| V4 投稿 | シングル（1 カラム） | V1・V2 → V5・V6・V7 | 「オブジェクトの情報がすべて並列な関係にある場合に利用」［H］`patterns/page-layout.mdx.txt:375` |

| V6 公開済みにする | モーダルダイアログ（FormDialog） | V4 から | 公開日と URL だけを入れる短いタスク［判断］ |

**ビューを増やさなかったもの**

- **「遅れ一覧」「空き週一覧」**：V1 の中の注意表示と、週の中の表示で伝える。別画面にすると「同じ画面に表示して編集したい内容が、別々の画面にある」［H］`ia/information-architecture.mdx.txt:39` に当たると判断した（遅れや空き週は、前後の週の予定と一緒に見ないと対処を決められない）。
- **カレンダー（月表示）**：smarthr-ui の `Calendar` は「WarekiPickerやDatePicker（非推奨）の内部部品として使われるため、単独では使用しません」［H］`components/00-component-selector.md:24`。月表示のグリッドは 390px で読めず、「水平方向のスクロールや2次元スクロールを避ける」［H］`patterns/page-layout.mdx.txt:116-118` にも反する。目標が「週 1 本」なので、**週を行にしたリスト**のほうが目標と単位が一致する［判断］。
- **メンバーの詳細ビュー**：上記 V3 の理由。
