# Ant Design 版のデザイン判断

原本（DADS 版）の判断は [digital-go-design-system `docs/design-decisions.md`](https://github.com/takumibv/digital-go-design-system/blob/codex/ct-schedule-ui/docs/design-decisions.md)、ADS 版の判断は [ads-ct-schedule/docs/design-decisions.md](../../ads-ct-schedule/docs/design-decisions.md) にあります。ここでは Ant Design（antd v6.7.0）で作り直したときに、何を引き継いで何を変えたか、その理由を記録します。各判断が Ant Design のハーネス（DESIGN.md、CLI、部品文書など）から来たのか、自分の判断なのかは [harness-report.md](harness-report.md) の出典表にまとめています。

## 基本方針

ADS 版と同じ 2 つの方針をとりました。

1. **中身は原本と同じにする。** 画面構成、読む順序、状態（16 種類）、文言、固定データ（`fixtures.ts`）は変えていません。
2. **見た目は Ant Design の標準に任せ、寄せるための上書きをしない。** 自前の CSS ファイルは 0 行です。テーマの変更は `ConfigProvider` のトークンだけで行い、値はすべて Ant Design 自身のパレットとスケールにある値を使いました（独自の色や数値は作っていません）。

ADS 版との違いは、**実装の前に Ant Design の DESIGN.md を読み、その原則に合わせた**ことです。たとえば「ページは灰色の背景、内容は白いカードに載せる（3 層モデル）」「1 回限りのアクセント色を作らない」は DESIGN.md から来ています。

### 書かざるを得なかった style

`style` 属性は 17 か所あります。値はすべて `theme.useToken()` のトークンから取りました。コード中では `STYLE:` コメントで理由を残しています。

| 場所 | 理由 |
| --- | --- |
| スキップリンク | antd にスキップリンクも「視覚的に隠す」部品もない |
| アバターの色 | `Avatar` に色の props がない。プリセット色トークン（1 段目＝背景、8 段目＝文字）を当てた |
| 自分のペアの行の背景、行の区切り線と余白 | `Listy` の行に「選択中」の表現がない |
| ロゴの反転（`filter: invert(1)`） | ロゴ SVG が黒（`currentColor`）。原本と同じく暗いヘッダー上で白く見せる |
| ヘッダー・本文・フッターの最大幅と左右の余白 | `Layout` に最大幅の props がない（`screenXL` = 1200px を使用） |
| `Layout.Header` の高さ・行間の解除 | Header は 64px 固定・行間 64px が既定で、2 段のヘッダーにできない |
| `minWidth: 0`（2 か所） | Flex の中で長い名前を折り返すため |
| 中央のアイコンの色、ヘッダーの文字色 | アイコン・素のテキストに色の props がない |

ADS 版は `xcss` で同じことを型安全に書けました（トークン以外の値は型エラー）。antd の `style` は何でも受け付けるので、**トークンを使うかどうかは書く人（AI）の規律に任されます。**

## 利用者と主役

原本と同じく、主な利用者は「月曜の CT 直前に相手を確認するメンバー」です。いちばん知りたいのは「今週の自分の相手は誰で、どこで話せばよいか」です。

- **「今週のあなたの CT」を主役にした。** 原本は濃い青の太い上ボーダー、ADS 版は薄い青の背景で目立たせていました。Ant Design 版では**色による強調をしていません。** DESIGN.md の「1 回限りのアクセント色を作らない。必要に見えるならレイアウトを見直すべき」「強調は行動のためだけに使う（Meaningful）」に従ったためです。代わりに次の 3 つで主役にしました。
  - 2 人のアバターを 64px で中央に並べる（一覧のアバターは 32px）
  - 画面で唯一の primary ボタン（large）「Slack でハドルを始める」を置く
  - 週の見出しのすぐ下、補足欄より先に置く
- 結果として、原本・ADS 版よりも主役の目立ち方は弱くなりました（後述の妥協点）。
- **画面内の primary は 1 つだけ**にしました。DESIGN.md、Button 文書の When To Use、設計仕様（buttons）のすべてに書かれています。一覧のハドルは default、表の操作は text、補足欄の「自分の参加設定を変更する」は link にしました。
- 未ログインの画面では、primary は案内（Alert）の中の「Slack でログイン」です。ヘッダーの「Slack でログイン」は default にして、2 つ並ばないようにしました。

## 画面ごとの判断

### 全体（ヘッダー・背景・フッター）

- **ページの背景は灰色（`colorBgLayout` #F5F5F5）、内容は白いカード**にしました。DESIGN.md の 3 層モデル（ページ → カード → 浮く面）に従っています。原本は白い背景に枠線で区切る作りなので、見た目はここがいちばん変わりました。
- ヘッダーは `Layout.Header` の既定色（濃紺 #001529）のブランドバーと、白いサービスバーの 2 段です。390px ではサービスバーの中身を折り返し、横にはみ出さないようにしました。
- 本文の最大幅は `screenXL`（1200px）です。原本は 1280px ですが、トークンにある値を優先しました。

### CT組み合わせ表

- **レイアウト**：PC は `Row`／`Col` で本文 16 列＋補足 8 列、モバイルは同じ順序で縦に積みます。
- **週の移動**：前後の矢印はアイコンだけのボタンにし、`aria-label` と `Tooltip` を付けました。設計仕様（buttons）の「アイコンだけのボタンには Tooltip で意味を示す」に従っています。
- **ハドルボタンのアイコンは 1 つ**にしました。原本と ADS 版は「吹き出し」と「外部リンク」の 2 つを付けていましたが、設計仕様（buttons）の Don't に「1 つのボタンにアイコンを 2 つ置かない」とあります。
- **みんなの組み合わせ**：antd v6.6 で `List` が非推奨になり、後継の `Listy` が入りました（CLI の `antd doc List` と `antd lint` で知りました）。そこで `Listy` を使い、1 ペアを 1 行にしました。自分のペアの行だけ `colorPrimaryBg`（#E6F4FF）を敷いています。DESIGN.md の「Menu の選択色が『現在地』を示す唯一の合図」と同じ色・同じ役割です。「あなた」は文字のラベル（Tag）でも示しています。
- **この先の CT**：原本と同じく 3 枚のカードを横に並べ、モバイルでは縦に積みます。カードの右上に「組み合わせを見る」アイコンボタン（Tooltip 付き）を置きました。祝日の週は警告色の Tag「祝日のためお休み」で区別します。
- **補足欄**：「CT に参加する人」は `Statistic` で人数を見せ、原本と同じく最初の 3 人のアバターを `Avatar.Group` で添えました。
- **祝日・参加者不足**：`Empty` に説明と次の行動のボタンを入れました。設計仕様（空状態）の「空の理由を伝え、次にできることを示す（Provide Invitation）」に合っています。

### メンバー一覧

- 上部に「参加する／参加しない」の人数を `Statistic` のカードで並べます。
- 一覧は `Table` です。DESIGN.md のとおり縞模様にはしていません。390px では「社員番号」の列を隠しました（`columns[].responsive`、CLI で取得した Table の `responsive` デモから）。
- **参加状況は Tag ではなく `Badge` の状態表示（点＋文字）**にしました。DESIGN.md の「状態には機能色を使う」「Tag は分類のためのもの」に従い、分類（あなた・設定未完了）と状態（参加する・しない）で部品を分けました。
- 「設定」「削除」は text ボタン（削除は `danger`）です。設計仕様（buttons）の「Text ボタンは表の中の操作のような、強調の低い操作に」に従いました。
- 削除の確認は `Modal` です。設計仕様（feedback）は「要素のそばで確認するなら Popconfirm」とも書いていますが、説明文と失敗時のエラー表示を入れる必要があり、原本の Story（`initialDialog`）も対話ボックスなので Modal にしました。**最初のフォーカスは「キャンセル」**です（原本と同じ。うっかり Enter で削除しないため）。

### 自分の設定・初回設定

- `Form`（`layout="vertical"`）と `rules` で検証します。必須の印は `requiredMark` で「（必須）」という文字にしました。antd の既定は赤い「*」で、日本語の画面では原本の「必須」の表記に寄せたほうが伝わると考えました。
- エラーは ADS 版と同じく 2 段構えです。上部の `Alert` で「何を直せばよいか」をまとめ、各項目の下に個別のエラー文を出します（`Form.Item` の標準の動き）。
- 参加の切り替えは `Checkbox` にしました。Checkbox 文書の When To Use に「Switch は即時に反映、Checkbox は送信と組み合わせる」とあり、この画面は保存ボタンで確定するためです。
- 保存ボタンは primary、キャンセルは default です。

### 読み込み中・読み込み失敗・404

- 読み込み中は `Spin`（large）と見出し、説明文です。
- 読み込み失敗は `Result status="error"` と「再読み込み」ボタンです。
- 404 は `Result status="404"`（イラスト付き）です。設計仕様（例外ページ）の「404 テンプレート：イラスト・コード・説明・次の行動」に従いました。

## 通知の使い分け

原本はすべての通知を画面内のメッセージで出していました。ADS 版と同じく、通知の性質で 2 つに分けました。部品の選び方は設計仕様（feedback）と Alert／Message の文書に従っています。

| 種類 | antd の部品 | 例 | 理由 |
| --- | --- | --- | --- |
| 状態が続くもの | `Alert`（その場に残る） | ログイン失敗、保存失敗、入力エラー、削除失敗、未ログインの案内、不参加中 | 設計仕様：「Alert は操作を中断しない静的な表示で、自動では消えない」 |
| 操作の結果を一時的に知らせるもの | `message`（上部中央、約 3 秒で消える） | 保存しました、削除しました、ハドル・ログインのデモ通知 | 設計仕様：「Message は操作の結果を伝える軽い通知。重要な失敗は対話ボックスで」 |

`message` は `App.useApp()` から呼びました。静的メソッド（`message.success()`）は `ConfigProvider` のテーマや言語を受け取れないためです（DESIGN.md の Customization と `antd lint` の usage ルールに書かれています）。

## 色の意味

色の意味を画面全体でそろえました。どの色も文字と組み合わせているので、色が分からなくても困りません。

| 色 | 部品 | 使った場所 | 意味 |
| --- | --- | --- | --- |
| 青（`processing`） | Tag | 今週 | 現在 |
| 青（プリセット `blue`） | Tag | あなた | 自分（分類） |
| 灰（`default`） | Tag | 来週以降の週ラベル、14:00 開始、今週のお休み | 中立の情報 |
| 黄（`warning`） | Tag | 祝日のためお休み、初回設定が未完了 | 注意してほしいこと |
| 緑／灰の点（`success`／`default`） | Badge | 参加する／参加しない | 状態 |
| 薄い青（`colorPrimaryBg`） | 行の背景 | 自分のペア | 現在地 |
| プリセット色（blue／green／purple／orange） | Avatar | 人ごとの色 | 分類（DESIGN.md「プリセット色はタグ・グラフ・分類専用」） |

### テーマの変更（すべて `ConfigProvider` のトークン）

| トークン | 既定 | 変更後 | 理由 |
| --- | --- | --- | --- |
| `colorPrimary` | #1677FF | #0958D9（blue-7） | DESIGN.md の注記「白文字 × #1677FF は AA 未満。厳密に満たすなら colorPrimary を暗くする」 |
| `colorInfo` | #1677FF | #0958D9（blue-7） | Tag `processing` の文字が 3.66:1 だった |
| `colorWarning` ＋ `colorWarningBg` | #FAAD14 ＋自動派生 | #874D00（gold-9）＋ #FFFBE6（gold-1） | Tag `warning` の文字が 1.82:1 だった。濃い seed から派生した背景が #C7C2B3 と濁ったので背景は戻した |
| `colorError` | #FF4D4F | #CF1322（red-7） | 項目のエラー文が 3.26:1 だった |
| `colorTextTertiary`、`colorTextDescription` | 0.45 の透過黒 | 0.65 の透過黒（`colorTextSecondary` と同じ） | 補足文が灰色の背景上で 3.29:1 だった |
| `fontFamily` | 欧文のシステムフォント | 先頭に `Noto Sans JP` | 和文の字形を OS に依存させない（原本と同じ） |
| `components.Typography.fontSizeHeading1〜4` | 38／30／24／20px | 30／20／16／16px | 見出しのレベルと大きさを分けるため（後述） |

**初回の axe では、antd の既定のままで 1 画面あたり 5〜33 件のコントラスト違反が出ました。** 上の 7 つのトークンを変えたあとは 0 件です。DESIGN.md が触れているのは `colorPrimary` だけで、状態色と補足文の灰色が AA を満たさないことは書かれていません（詳しくは harness-report.md）。

## 日本語 UI

- `ConfigProvider locale={jaJP}` で、Modal の既定ボタンや Table の空表示などを日本語にしました。
- フォントは原本と同じ Noto Sans JP をローカル配信し、400 と 600 の 2 種類だけ読み込みました。DESIGN.md の「製品 UI で使う太さは 400 と 600 の 2 つだけ」に従っています。原本は 400／500／700 です。
- 見出しは h1 = 30px、h2 = 20px、h3 = 16px にしました。`Typography.Title` は `level` が見出しのレベルと大きさを同時に決める（h1 = 38px、h2 = 30px…）ため、そのままだと「みんなの組み合わせ」のような h2 が 30px になります。最初はグローバルのトークンを変えましたが、`Statistic`・`Result`・`Modal`・`Alert` も同じトークンを使っていて、人数の数字が 16px に縮みました。DESIGN.md の「部品単位で、その部品が使うエイリアストークンを上書きできる」に従い、`components.Typography` だけに限定しました。
- フォームの検証メッセージは antd の日本語の既定文（「〜は必須です」）を使わず、原本の文言を `rules` に書きました。

## アクセシビリティ

- 「本文へ移動」のスキップリンクを置き、キーボードで操作したときだけ表示されるようにしました（antd に部品がないため自作）。
- `Flex` の `component` で `section`／`aside` を指定し、ページの構造が支援技術に伝わるようにしました（ADS の `Stack` はこれができませんでした）。
- 見出しは h1 → h2 → h3 の順です。
- アイコンだけのボタンには `aria-label` と `Tooltip` を付けました。
- アバターは名前と並べて表示するので `aria-hidden` にしました。
- antd v6 は既定で `body` の余白などをリセットしません。そのため削除確認のモーダルを開くと、スクロールを止める処理と `body` の 8px の余白が重なり、横に 8px はみ出していました。公式の `antd/dist/reset.css` を読み込んで解消しました（llms.txt の索引から読んだ「compatible-style」文書で、reset.css の存在を確認）。
- axe（WCAG 2.1 AA）は 16 状態 × 2 幅のすべてで 0 件、横はみ出しも 0 です。

## 再現できなかったこと（妥協点）

| 原本の意図 | Ant Design 版でどうなったか | 理由 |
| --- | --- | --- |
| 「今週のあなたの CT」を濃い青の太い線と色面で強調 | 白いカード。強調はアバターの大きさと primary ボタンだけ | DESIGN.md の「1 回限りのアクセント色を作らない」に従った。主役の目立ち方は原本・ADS 版より弱い |
| 白い背景に枠線で区切る、すっきりした画面 | 灰色の背景に白いカードを並べる、管理画面らしい見た目 | DESIGN.md の 3 層モデル |
| 本文 16px、見出し 32px のゆったりした文字 | 本文 14px、見出し 30／20／16px | antd の基本は 14px（DESIGN.md「業務画面の情報密度のため 16 ではなく 14」）。本文の大きさは変えていない |
| 太さ 400／500／700 | 400／600 | DESIGN.md の「太さは 2 つだけ」 |
| 濃い青 #0017C1 の主色 | #0958D9（antd の blue-7） | antd のパレットにある値を優先した |
| 操作結果の通知が画面内に残る | `message` で約 3 秒後に消える | 設計仕様（feedback）に従った。読み上げに時間がかかる人には短い可能性がある（未検証） |
| 390px でも表が読みやすい | 「参加状況」の列が狭く「参加／する」と折り返す | 社員番号の列は隠したが、列そのものを縦並びにする機能は Table にない |
| 外部リンクであることをアイコンで示す（↗） | 示していない | 「アイコンは 1 つ」を優先した。Slack に移ることは文言で伝わると判断した |

## まとめ

**DESIGN.md を先に読んだことで、「主役をどう目立たせるか」の判断が原本・ADS 版と変わりました。** 色を足さず、大きさと 1 つの primary ボタンだけで主役を作る、というのは DESIGN.md の原則どおりの答えです。その結果、画面は Ant Design らしい落ち着いた管理画面になり、原本の「市民向けのやさしさ」からはさらに遠ざかりました。また、DESIGN.md のとおりに既定のテーマを使うと AA を満たさない箇所が多く、トークンを 7 つ変える必要がありました。
