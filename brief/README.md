# CTスケジュール 設計ブリーフ（デザインシステム比較用）

この文書は、CTスケジュールを**白紙から**設計・実装するためのブリーフです。各デザインシステムで同じブリーフから作り、「目的を達成できているか」と「AI 向けハーネスがどう効いたか」を比べるために使います。

**画面の見本はありません。** レイアウト、画面の数や分け方、部品の選び方はすべて自由です。使うデザインシステムの流儀と、そのハーネス（MCP、スキル、llms.txt、DESIGN.md、lint など）が示す考え方に従って決めてください。

## このアプリについて

チーム内で毎週月曜に行う 2 人 1 組の雑談（CT＝コミュニケーションタイム）について、組み合わせを自動で決め、全員がいつでも確認できるようにするアプリです。

- **主な利用者**：チームメンバー全員。全員が閲覧者で、ログインした人は自分の設定も変えられる。
- **主な利用シーン**：月曜の CT 前に「今週の相手は誰か」を確かめ、そのまま相手との通話（Slack ハドル）を始める。滞在は数十秒で終わる。
- **たまに起きること**：初めて使う人の設定、休職などで参加をやめる・戻る、退職者を外す。
- **画面の外で起きること**：毎週月曜 11:00 に、その週のペアが Slack チャンネルへ自動投稿される（CT 自体は 14:00 開始）。アプリはこの投稿からのリンク先にもなる。

## 達成したい目標

| # | 目標 | 誰のどんな瞬間か |
| --- | --- | --- |
| G1 | 開いてすぐ「今週、自分は誰と話すか」がわかる | 月曜の CT 直前、Slack の投稿やブックマークから来た人 |
| G2 | その相手との通話をすぐ始められる | 同上 |
| G3 | 先の週の予定（来週は誰か、次にお休みになるのはいつか）を確かめられる | 予定を気にする人 |
| G4 | 誰が組み合わせに入っているかを確かめ、いなくなった人を安全に外せる | まれに管理する人 |
| G5 | 自分の参加状況（休職・繁忙期で抜ける／戻る）を変えられ、その影響が伝わる | 状況が変わった人 |
| G6 | 初めての人が迷わず必要な設定を終えられる | 初回ログインした人 |
| G7 | どんな状態（読み込み中、失敗、データなし など）でも、何が起きていて次に何をすればよいかがわかる | 全員 |

## 組み合わせのルール（変えない）

1. 毎週月曜に 1 回、参加者全員を 2 人ずつのペアに分ける。
2. 毎週相手が変わる（ラウンドロビン）。
3. 参加者が奇数の週は 1 人が「お休み」。お休みの人も週ごとに入れ替わる。
4. 祝日の月曜は CT なし。その週は組み合わせを作らず次の週へ繰り越す。祝日名を示す。
5. 参加している人だけが対象。参加者が 2 人未満なら組み合わせは空。
6. 並び順は社員番号順。
7. 参加者が増減すると、その週以降の組み合わせは組み直しになる。先の週の組み合わせは「予定」であり確定ではない。

※ 組み合わせの計算は実装しなくてよい。`fixtures.ts` の固定データを使う。

## 機能要件

### サイト全体

- Gaji-Labo のサービスであることがわかる（`gaji-labo-logo.svg`。押すと https://www.gaji.jp/ が別タブで開く）。
- 今どの画面（または場所）にいるかがわかる。組み合わせの表示へいつでも戻れる。

### ログイン・ログアウト

- どこからでも Slack アカウントでログインできる（ログイン手段は Slack のみ。デモでは通知を出すだけでよい）。
- ログイン中は、自分が誰としてログインしているか（アイコン・名前）が常にわかる。
- ログアウトできる。
- ログインしていなくても、組み合わせとメンバーは見られる。

### 組み合わせの表示

- 今週（今日を含む週の月曜）の組み合わせと、それ以降の週の組み合わせを見られる。過去の週は出さない。
- 各週に出すもの：日付（曜日つき）、ペアの一覧、お休みの人（奇数のとき）。
- 祝日の週は「CT なし」であることと祝日名を示し、ペアは出さない。
- 人の表示：アイコンと名前。アイコンが無い人は名前の頭文字で代用し、人ごとに固定の色で見分けられるようにする（`fixtures.ts` の `color`）。
- ペアごとに、相手の uチャンネル（個人用 Slack チャンネル）でハドルを始める導線を置く。uチャンネル未設定の人とのペアでは出さない（デモでは通知を出すだけでよい）。
- 今の参加者数がわかり、メンバーの確認へ移れる。
- CT の開始時刻（月曜 14:00）がわかる。
- ログイン中なら、自分のペア（またはお休みであること）を探さずにわかる。
- 先の週は「予定」であることが伝わる。
- ログインしていない人に、ログインすると何ができるかが伝わる。

### メンバー

- ログインしたことのある全員を、社員番号順に見られる。
- 各メンバーのアイコン、名前、参加／不参加がわかる。参加と不参加は色だけに頼らず区別できる。
- 参加者数と不参加者数がわかる。
- 初回設定が済んでいない人（社員番号や uチャンネルが未設定）がわかる。
- 自分がわかり、そこから自分の設定を変えられる。
- ログイン中の人はメンバーを削除できる（退職者など）。取り消せない操作として、誰を削除するかを確認してから実行し、結果（成功／失敗）を伝える。

### 自分の設定（初回設定を含む）

| 項目 | 必須 | 何に使うか |
| --- | --- | --- |
| 名前 | 必須 | 表示名。Slack の表示名が初期値 |
| 社員番号 | 必須 | 並び順の基準。半角数字 |
| uチャンネル | 必須 | 相手がハドルを始める個人用チャンネル（`u-` で始まる）。既存の一覧から選ぶ |
| CT に参加する | — | 組み合わせに入るか。初期値は「参加する」 |

- 初回ログインした人には、必須項目が埋まるまで入力を求める。
- あとからいつでも変えられる。参加をやめる／戻ると全員の組み合わせが変わることが伝わる。
- 変えられるのは自分の設定だけ。
- 保存の成否を伝える。

### 状態

次の状態それぞれで、何が起きていて次に何をすればよいかがわかること。**これらは URL のクエリなどで直接開けるようにする**（撮影と比較のため）。

| ID | 状態 |
| --- | --- |
| S01 | 今週・ログイン中（通常） |
| S02 | 未ログイン |
| S03 | 自分が今週お休み（ログイン中。`fixtures.ts` の id=9 の人として） |
| S04 | 祝日の週を表示中 |
| S05 | 参加者が 2 人未満 |
| S06 | 読み込み中 |
| S07 | 読み込み失敗（やり直す手段つき） |
| S08 | Slack ログインに失敗（やり直す手段つき） |
| S09 | 今週の相手の uチャンネルが未設定（id=2 の人の uチャンネルが未設定とする） |
| S10 | 設定の保存に成功した直後 |
| S11 | メンバーの一覧（ログイン中） |
| S12 | メンバーが 0 人 |
| S13 | メンバー削除の確認中 |
| S14 | メンバー削除に失敗 |
| S15 | 初回設定（未入力） |
| S16 | 初回設定で必須項目が未入力のまま送信した |
| S17 | 設定の保存に失敗 |
| S18 | 存在しないページ（戻る手段つき） |

## 固定データ

`fixtures.ts`：架空のメンバー 11 人（id=10 は不参加、id=11 は初回設定が未完了で不参加）と 5 週分の組み合わせ。今週は 2026-10-05（月）とする。2026-10-12 はスポーツの日。ログイン中の自分は id=1。

## 決まっていないこと（自由に決めてよい。決めた理由を記録する）

- ハドルを「どちらの uチャンネル」で始めるか。
- メンバー削除をログイン中の全員に許すか。
- 先の週をどこまで見せるか。
- スマートフォンでの利用をどこまで想定するか（390px 幅でも使えることは確認する）。
- 「特定の人と次に当たるのはいつか」を調べる機能を入れるか。
- 参加者数の数え方（参加者だけか、全メンバーか）。

## 制約

- 部品・色・余白・文字は、指定されたデザインシステムのものを使う。自前の CSS は原則書かず、書いた場合は理由を記録する。
- 文言は日本語。
- 組み合わせのルールは変えない。
